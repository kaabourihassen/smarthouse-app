# SmartHouse Infrastructure & Deployment (`.infra`)

This directory contains all the Infrastructure as Code (IaC), containerization, configuration, and monitoring assets required to deploy the SmartHouse application locally or to a production Kubernetes cluster.

## 📁 Directory Structure

* **`compose/`**
  Contains Docker Compose files for easy deployment without a full Kubernetes cluster.
  * `docker-compose.dev.yml`: Local development environment (mounts volumes for live reloading).
  * `docker-compose.production.yml`: Production-ready stack utilizing the built Docker images.

* **`dockerfiles/`**
  Contains the instructions for building the container images for the application components.
  * `api.dockerfile`: Multi-stage build for the NestJS backend.
  * `client.dockerfile`: Multi-stage build for the Angular frontend, utilizing NGINX for serving the built assets.

* **`helm/`**
  Contains the **Helm Chart** (`smarthouse`) for deploying the entire application stack to Kubernetes. This is the recommended deployment method for production.
  * `Chart.yaml`: Helm chart metadata.
  * `values.yaml`: Default configuration values. **(Ensure you provide your own secrets!)**
  * `templates/`: Kubernetes manifests generated by Helm (Deployments, Services, Ingress, Secrets, etc.).

* **`k8s/`**
  Contains helper scripts and supplementary Kubernetes resources.
  * `deploy-k8s.sh` / `deploy-k8s.ps1`: Convenience scripts to automate the deployment process to your cluster.
  * `node-exporter-ds.yaml`: DaemonSet for Prometheus Node Exporter to gather cluster hardware metrics.

* **`prometheus/` & `grafana/`**
  The monitoring and observability stack.
  * **Prometheus**: Configurations (`prometheus.yml`, `scrape.yml`) for scraping metrics from the NestJS backend and cluster nodes.
  * **Grafana**: Provisioning configurations and datasources (e.g., connecting to Prometheus) to power your observability dashboards.

* **`mongodb/`**
  Contains initialization scripts for the database.
  * `initdb.js`: Executed when the MongoDB container starts for the first time to set up users, databases, and initial collections.

* **`nginx/`**
  Contains configuration files for the reverse proxy and static file server.
  * `nginx.conf`: Base NGINX configuration.
  * `k8s-client.conf`: Specific configuration for serving the built Angular application within the Kubernetes pod.

## 🚀 Deployment Guides

### 1. Local Development (Docker Compose)
The easiest way to spin up the entire stack locally for testing.

```bash
cd .infra/compose
docker-compose -f docker-compose.dev.yml up -d
```

### 2. Production (Docker Compose)
To run the production-ready images locally or on a single VM. Note that you need to build the images first using the files in the `dockerfiles/` directory, or ensure they are pulled from your registry.

```bash
cd .infra/compose
docker-compose -f docker-compose.production.yml up -d
```

### 3. Production (Kubernetes / Helm)
To deploy the application to a Kubernetes cluster using Helm.

```bash
cd .infra/helm
# Install or upgrade the release named 'smarthouse-prod'
helm upgrade --install smarthouse-prod ./smarthouse -f ./smarthouse/values.yaml
```
*(Alternatively, use the provided script in `.infra/k8s/deploy-k8s.sh` or `.infra/k8s/deploy-k8s.ps1`)*

## ⚠️ Security Notice
Always ensure that your production `values.yaml`, `.env` files, and `secret.yaml` templates do **not** contain hardcoded plaintext secrets (like Stripe API keys, OpenAI keys, or database passwords) before committing to version control. Use a secret manager (like AWS Secrets Manager, HashiCorp Vault, or Kubernetes Secrets) injected at runtime or deployment time.
